# EN8811H v2.0.7 port for the Airoha target

This ports the MediaTek/Airoha EN8811H v2.0.7 driver changes to PonWrt's
Linux 6.18 driver. The immediate use case is the Nokia 040G 2.5G port that
can negotiate a copper link but stop passing traffic until power is removed.
The port is prepared without access to a device. Compilation does not prove
that it fixes that fault, and a PHY link does not establish that the host PCS
or MAC data path is working.

## Source and scope

- PonWrt base: `c3b518baec8ed0cc5a353327fa154f38bde1e6c0`, Linux 6.18.52.
- Vendor source: [EN8811H v2.0.7 patch in immortalwrt-mt798x](https://github.com/Yuzhii0718/immortalwrt-mt798x-6.6-padavanonly/blob/118e857cd2a2cacb05ee4ae90fef0c4df21be3dc/target/linux/mediatek/patches-6.6/999-ephy-en8811h-01-update-driver-to-v2.0.7.patch).
  Its original author is Mason Chang (MediaTek), dated 2026-01-09.

The new target patch applies after PonWrt's generic EN8811H backports. It
retains the Linux 6.18 clock provider, standard polarity properties with the
legacy property fallback, the LED-off fix, and GPIO function reconfiguration
on every `config_init`.

The vendor firmware-start and MCU-restart sequences are carried over:

- Set the internal-control bit around firmware startup/restart, and clear
  the firmware-ready status before asking the MCU to restart.
- Write the vendor initialization values at `0x1e00d0` and `0x1e0228`.
- Preserve the vendor distinction between the first initialization and
  subsequent MCU restarts, and clear internal control at the matching stages.
- Carry over the duplex/pause status ordering and LED blink duration.

The optional vendor debugfs interface is also included, with input validation,
MDIO page/lock cleanup, error handling, and managed-allocation fixes. Clock
context restoration is limited to this PHY's existing clock provider; it
does not invoke a global SoC clock restore from a PHY resume callback.
The PHY suspend snapshot is separate from the clock provider's snapshot and
becomes valid only after a successful suspend. This avoids changing CKO on
the unconditional resume call during the first PHY attachment.

This patch does not change board reset timings, DTS wiring, PCS negotiation,
or the firmware package. It does not add an automatic watchdog for a link
that is up but cannot pass traffic. Both compared repositories already use
the same EN8811H firmware binaries, so replacing those binaries is outside
the scope of this driver port.

## Optional diagnostics

`CONFIG_AIR_EN8811H_PHY_DEBUGFS` defaults to off and requires both the
EN8811H driver and `CONFIG_DEBUG_FS`. Enable it in the kernel configuration
when a diagnostic build is needed. Its entries are created below debugfs
under the PHY device name.

Some entries write registers, restart the MCU, or run link tests. Use those
only during a maintenance window with another way to reach the device.
The default firmware build leaves this interface disabled.

## Software validation

Run the reproducible check on Linux:

```sh
bash scripts/ci/check-en8811h.sh /tmp/en8811h-check
```

The script reads PonWrt's pinned kernel version and SHA256, downloads that
kernel, applies the relevant generic PHY backports and this target patch with
zero fuzz, then compiles the driver as an ARM64 module with PHY LED support.
It checks three configurations: driver diagnostics enabled, driver
diagnostics disabled with global debugfs enabled, and global debugfs disabled.
Compilation uses `W=1` and `KCFLAGS=-Werror`; configurations, logs, and object
files are saved in the selected output directory.

On x86-64 Linux, install `gcc-aarch64-linux-gnu`. Both native ARM64 and cross
builds need the usual kernel build dependencies (make, GCC, bc, bison, flex,
OpenSSL and ELF development headers), plus curl, xz, patch, and file.
The `EN8811H driver compile` GitHub Actions workflow runs the same check and
can be started manually. It does not build or publish complete device images.

## Checks still requiring a device

Before using an image operationally, test cold boot and repeated soft reboots,
2.5G and 1G copper partners, cable reconnection, and sustained bidirectional
traffic. Capture the kernel log and PHY/PCS/MAC counters when the link is up
but traffic stops, before power cycling. Test the exact 040G suffix because
the AN7581 and AN7583 variants use different host ports and reset GPIOs.

Suspend/resume and the writable diagnostic commands also require runtime
verification. A full PonWrt image build and hardware tests are separate from
the driver compilation check.
